Tasker Automation

Type a short trigger anywhere you're typing and the keyboard hands your text to a Tasker task, then drops the task's answer straight back into the field - no app-switching required.

The idea
Tasker Automation lets you define your own tiny "commands" that work in any text field, in any app - a note, a chat, an email, a form. You type a short trigger, the keyboard silently sends the surrounding text to a Tasker task, and whatever that task sends back is inserted for you.
You type ##fix → Keyboard calls Tasker task "fix" → Task replies with text → Keyboard inserts the reply
Because the task itself is just a normal Tasker task, it can do anything Tasker can do: call an AI/HTTP API, do maths, look up a contact, translate text, format a date, run a local script - the keyboard doesn't care, it only cares about the text that comes back.
Three trigger styles, one engine: ## replace, @@ append, and open-ended .. expand patterns. They all call Tasker the same way; they only differ in how much of the field gets sent and how the result is inserted - each is covered in its own section below.
One-time setup
Before any trigger will work, three things need to be true:
  1. Tasker is installed on the device (the free trial or paid version both work).
  2. Allow External Access is enabled in Tasker, at Tasker → ☰ Menu → Preferences → Misc → Allow External Access. This is what lets any other app (including this keyboard) ask Tasker to run a task and get a reply back.
  3. The task exists in Tasker, and its name matches exactly what you put in the keyboard's config (case-sensitive) - see the Config file section below.
  • If you skip step 2: every trigger will still "fire" (the trigger text disappears), but you'll get a toast saying Tasker couldn't be reached, and nothing useful will be inserted.
Need ready-made example tasks instead of building one from scratch? Open Settings → Tasker Automation → Get AM Tasker Plugins for a small collection of starter tasks and plugin actions you can import - including the "AM Custom Keyboard Return" plugin covered under Building the Tasker task below.
The config file
Everything lives in one JSON block, edited from Settings → Tasker Automation. Open it and you'll see a small editor with line numbers and live validation - it won't let you save invalid JSON.
{
  "amck_replace": "##",          // trigger symbol for whole-field replace
  "amck_append": "@@",           // trigger symbol for insert-in-place
  "amck_timeout": "15000",       // ms to wait for Tasker's reply

  "runtask1": "Fix Grammar",     // keyword "runtask1" -> Tasker task "Fix Grammar"
  "translate": "Translate to EN",

  "amck_patterns": [      // optional, open-ended patterns (see below)
    { "prefix": "..", "suffix": " ", "task": "Calculator" }
  ]
}
amck_replaceText
##
Symbol that starts a "replace the whole field" trigger.
Default: ##
amck_appendText
@@
Symbol that starts an "insert in place" trigger.
Default: @@
amck_timeoutNumber (ms)
15000
How long to wait for the task's reply before giving up. Allowed range: 1000-120000.
Default: 15000
amck_patternsArray
{ "prefix": "..", "suffix": " ", "task": "Calculator" }
List of open-ended prefix ... suffix expanders, optionally with a regex too - see the Expand patterns section below.
Default: one example entry
any other keyText
"runtask1": "Fix Grammar"
A keyword you'll type after the trigger, mapped to a Tasker task name.
Any of the amck_ keys can simply be left out - the editor auto-fills the defaults for you and shows them the next time you open it, so you always see (and can override) every setting in one place. amck_replace and amck_append must be different from each other, and you need at least one task keyword configured.
Automation Builder (no JSON required)
Don't want to hand-write JSON at all? Settings → Tasker Automation → Automation Builder opens a guided form editing this exact same config - the two screens always agree, and you can switch between them freely.
  • A fixed section for amck_replace / amck_append / amck_timeout - always exactly those 3 fields.
  • An add/remove list of keyword → Tasker task name rows, for the replace/append triggers.
  • An add/remove list of expand pattern cards, one per amck_patterns entry, with prefix / regex (optional) / suffix / task stacked so each stays readable on a phone-width screen.
Every field holds exactly what you type - nothing is trimmed or re-escaped. A prefix or suffix that's just a single space stays a space, and typing \n (backslash, then n) into a suffix field saves the same way "suffix": "\n" would if you'd typed it directly into the JSON editor - it isn't doubled into \\n. Opening the builder on an existing config shows this the same way back: a saved \n suffix displays as the visible text \n, not an actual line break.
Saving runs through the exact same checks as the JSON editor (non-empty prefix/suffix/task, no duplicate keyword, no duplicate prefix+suffix pair, valid regex, timeout range, distinct replace/append triggers) - anything invalid is flagged inline instead of being saved.
## replace trigger
Type amck_replace immediately followed by a configured keyword (e.g. ##runtask1) anywhere in a text field. The moment the last character of the keyword is typed:
  1. The whole field is captured. Everything currently in the field (before and after the trigger you just typed) is read.
  2. The task runs. The keyword's task launches in Tasker, receiving the field's text (split around where you typed the trigger) as variables.
  3. The whole field is replaced. Once the task replies, its output text becomes the field's entire new content - anything that was there before is gone.
Config
"runtask1": "Fix Grammar"
You type
i seen him yesterday he was'nt happy##runtask1
Output
I saw him yesterday; he wasn't happy.
The trigger can be typed at the end, in the middle, or even at the very start of the text - it doesn't have to be the last thing in the field, it just marks the spot where the command was entered. The task still receives the full field, split into "before the trigger" / "after the trigger".
  • Whole-note grammar/spelling cleanup
  • Tone changes across a whole message
  • Summarizing a paragraph
  • Translating an entire message
  • Reformatting a block of text
@@ append trigger
Works exactly the same way as replace, except only the typed amck_append+keyword text itself gets swapped out - everything else in the field is left completely untouched.
Config
"today": "Insert Today Date"
You type
Meeting notes — @@today — attendees:
Output
Meeting notes — 12 Aug 2026 — attendees:
  • Dropping in a computed date/time
  • Inserting a converted currency amount
  • Quick translation of one phrase
  • Generating a random ID
  • Looking up a contact's phone number
.. expand patterns
Replace/append triggers only work with a fixed list of keywords you typed out in the config. Expand patterns are different: they work with any free-form text you type between a prefix and a suffix - nothing to pre-register.
Type prefix, then anything (at least one character), then suffix. As soon as the suffix completes, the text in between is sent to the task as %keyword, and the whole prefix + content + suffix span is swapped for the task's reply - same "insert in place" behaviour as an @@ trigger.
Config
{ "prefix": "..", "suffix": " ", "task": "Calculator" }
You type
Total: ..12*3.5
Output (the moment the trailing space is typed)
Total: 42
Here %keyword received by the task is 12*3.5 - the task just needs a "Variable Set" action doing the arithmetic and sending it back. You can define as many expand patterns as you like, each with its own prefix/suffix/task, as long as no two entries share the exact same prefix+suffix pair.
regexText, optional
{ "prefix": "==", "regex": "\d+.+\d", "suffix": "\n", "task": "doMath" }
Restricts a pattern so it only fires when the content between prefix and suffix matches this regex in full (like wrapping it in ^...$) - a partial match doesn't count. If it doesn't fully match, nothing happens: no task runs and nothing is deleted, so you can just keep typing until it does. In the example, ==59+3 fires (the content is all digits/operators start to end), but ==1+6 with a trailing space before the newline does not, since it no longer ends in a digit.
The content a pattern ever sees can't contain a newline regardless of the regex, so . in a regex here already can't accidentally span multiple lines. When editing the raw JSON directly (not through the Automation Builder above), backslashes in regex specifically don't need doubling - type \d as-is rather than \\d.
Default: none (any non-empty content matches)
  • Unit conversions, e.g. ~10km
  • Quick inline maths
  • Smarter emoji/shortcut expansion
  • Looking something up online and pasting the result
  • Snippet expansion with dynamic content
Building the Tasker task
Any task you reference from the config just needs to exist in Tasker under that exact name - you don't need a Profile or Event to "catch" the call, Tasker's own External Access receiver handles that automatically once it's enabled (see One-time setup above). You only need to make sure the task sends its answer back before it finishes. There are two ways to do that:
METHOD 1Tasker's built-in "Send Intent" action
  1. Create the task in Tasker and give it the name you used in the config (e.g. Fix Grammar).
  2. Use the input variables. Inside the task you can reference %text1, %text2 and %keyword directly (see the Variables reference below) - do whatever processing you need and store the result in a local variable, e.g. %result.
  3. Add a final "Send Intent" action with these fields: 
    Action:  <your app id>.TASKER_RESULT
Extra:   requestid:%requestid
Extra:   text:%result
Target:  Broadcast Receiver
    Replace <your app id> with this app's own package name (e.g. com.adiraimaji.customkeyboard, or with a .debug suffix on a debug build) - the keyboard is listening for exactly this broadcast, tagged with the same %requestid it handed the task, so the reply gets matched to the right in-progress request even if you fire off several triggers back to back.
  • Don't use Tasker's built-in "Return" value instead - it might seem natural to add a Task → Return action, but Tasker's own ACTION_TASK_COMPLETE/Return mechanism doesn't reliably deliver a value to apps outside Tasker. The Send Intent broadcast above is the one that's actually being listened for.
METHOD 2The "AM Custom Keyboard Return" plugin action (no manual Send Intent needed)
If you have the companion AM Tasker Plugins app installed, it ships a ready-made plugin action - AM Custom Keyboard Return - that does exactly what Method 1's Send Intent action does, with the action name, package, target, and requestid wiring all pre-filled for you. The only thing you fill in is the text to send back.
  1. Install AM Tasker Plugins - get it from github.com/adiraimaji/AMTaskerPluginsReleases (also reachable from Settings → Tasker Automation → Get AM Tasker Plugins).
  2. Add its action as the last step of your task: Plugin → AM Tasker Plugins → AM Custom Keyboard Return.
  3. Fill in "Return Text" with the value to send back (type it directly, or tap the arrow button to insert a Tasker variable such as %result).
  4. That's it - requestid is already hardcoded inside the plugin to the Tasker variable %requestid, so it's always sent correctly without you having to add or edit anything for it.
Method 2 is the faster, less error-prone option since there's no action string, extras, or target to type out by hand - it's a good default unless you'd rather keep your tasks free of an extra app dependency, in which case Method 1 works exactly the same way from Tasker's own broadcast.
Variables reference
What the task receives
%text1
The field's text before the trigger/pattern you typed (with the trigger itself removed). Always set, can be empty.
%text2
The field's text after the trigger/pattern. Left completely unset (not just empty) when there's nothing there, so a Tasker "If %text2 Set" check behaves as expected.
%keyword
Just the keyword itself for a ##/@@ trigger (e.g. runtask1), or the free-form text between prefix and suffix for an expand pattern. Never includes the trigger symbols.
%requestid
A unique id for this specific call - echo it back unchanged (Method 1: as the requestid extra; Method 2: automatic, nothing to do).
What the task must send back
requestid
The exact same value received in %requestid.
text
The text you want inserted into the field.
Undo & a few edge cases
  • One-shot undo: right after a task's result lands in the field, a single, immediate backspace swaps it back for what you originally typed (the trigger+keyword, or the matched expand span) instead of deleting one character. Doing anything else first - typing another character, moving the cursor - forfeits that undo, and a backspace after that behaves normally.
  • Typo tolerance: if you mistype a keyword (e.g. ##ond instead of ##one) and backspace to correct it, the keyboard re-reads the text that's actually still sitting in the field, so finishing the correct keyword still fires the trigger - you don't have to retype the whole thing from scratch.
  • Results are toasted too: whenever a task replies successfully, its raw output is also shown briefly as a toast - handy while you're testing a new task, so you can see exactly what came back even before checking the field.
Troubleshooting
  • "Could not reach Tasker. Is it installed and is 'Allow External Access' enabled?" - Tasker isn't installed, or Allow External Access is off. Turn it on at Tasker → Preferences → Misc, then try again.
  • "Tasker task timed out or did not respond" - the task never sent back a matching reply within amck_timeout ms. If using Method 1, double-check the Send Intent's action string, the requestid extra, and that its target is Broadcast Receiver. If using Method 2 (the plugin), confirm AM Tasker Plugins is installed and the action is the last step in the task. If the task genuinely needs longer (e.g. a slow API call), raise amck_timeout (max 120000 ms).
  • Nothing happens at all when I finish typing the trigger - check the keyword in the config matches exactly what you typed (case-sensitive), and that amck_replace/amck_append aren't accidentally the same symbol as each other.
  • An expand pattern never fires - make sure there's at least one character of content between the prefix and suffix; an empty match (prefix immediately followed by suffix) is ignored on purpose, so ordinary punctuation doesn't misfire.
